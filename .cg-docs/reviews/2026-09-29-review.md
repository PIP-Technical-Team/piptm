### P2 — IMPORTANT (should fix)
- **[P2.1]** [cg-testing] tests/testthat/test-api-description.R:227 — The "both description_metadata and params supplied" 400 test and the 422 "metadata missing params" test don't set `format`, so they don't confirm error responses stay independent of the new default regardless of whether `format` is omitted.
  **Why**: Error paths currently return before `format` is read, so this is safe today, but the interaction isn't explicitly asserted — a future refactor moving format resolution earlier could silently make error bodies HTML instead of JSON without a test catching it.
  **Fix**: Add a comment or assertion in the 400/422 tests confirming `Content-Type: application/json` (or equivalent) is returned regardless of omitted `format`, to guard against format-resolution being hoisted above validation later. [advisory]
- **[P2.2]** [cg-testing] tests/testthat/test-api-description.R:212 — No test for an explicitly empty-string `format = ""` (or JSON `null`) value verifying it either defaults to HTML or is treated as invalid.
  **Why**: `%||%` only substitutes on `NULL`; an explicit JSON `null` typically deserializes to `NULL` in R via jsonlite, but an empty string `""` would not trigger the default and would instead need explicit validation — this boundary isn't covered.
  **Fix**: Add a test case with `format = ""` (and/or JSON `null`) asserting it hits the same 400 invalid-format path as `"pdf"`, or the html-default path, whichever is intended. [advisory]
