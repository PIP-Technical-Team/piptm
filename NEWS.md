# piptm (development version)

## piptm 0.1.0.9000

### Breaking changes

- `table_maker()` now requires `analysis_var` as an explicit input parameter.
- `table_maker()` and `/table` use scalar `poverty_line` (singular) instead of repeatable `poverty_lines`.
- `/table` input validation now enforces `poverty_line` when `analysis_var = "pov_status"` or when `"pov_status"` is present in `by`.
- **`pop_share_threshold` default changed from `0.01` to `0.001`** (10x more permissive). Per the reproducibility constraint that identical inputs must produce identical results, this changes which cells are masked vs. reported for any caller that does not pass an explicit `pop_share_threshold`: cells with a population share between `0.001` and `0.01` that were previously masked (`"NR"`) are now reported. Re-running prior analyses/scripts that rely on the default will **not** reproduce the same suppression pattern as before this version. Pipelines that depend on a stable disclosure-control threshold should pin `pop_share_threshold` explicitly rather than rely on the default.
- **Suppression scope changed: share-family measures (`pop_share`, `target_within_group_share`, `target_survey_share`) are no longer exempted from masking.** Previously, a suppressed cell retained its share-family values (dropping only the other measures) so callers could inspect the suppressed group's distribution; now every measure for a masked cell — including the share-family ones — is set to `NA` with `flag = "NR"`. This is an independent, intentional behavior reversal bundled with the threshold-default change above; treat them as two separate changes when auditing output differences.
- **The `population` column is removed entirely from `table_maker()`'s returned table**, not only from the `/table` API response. This is a breaking change to the computation engine's output schema for every direct caller (scripts, other packages), not merely a display/formatting change. No first-party internal `compute_*` function reads this output column (each computes and uses `population` internally before `table_maker()` drops it), but external callers referencing `table_maker()$population` will break.
- `table_maker()` replaces row-dropping cell suppression with cell-level masking (`value = NA`, `flag = "NR"`) at default `pop_share_threshold = 0.001` (0.1%), and removes the `population` column.
- The `/table` API endpoint now returns `value` as formatted strings via `format_table_output()`, with percentage measures scaled by 100 with 2 decimal places, whole-number counts, `"NR"` for masked cells, and `null` for genuine missing values. The `flag` and `population` columns are not included in `/table` response data.
- Added `format_table_output()` to format `table_maker()` data.tables according to the API presentation contract.
- **`/table` response shape reshaped to Approach C (`layout` + dense `cells[]`)**: With `include_metadata = false`, `/table` now returns an array of per-survey objects in `data`. Each survey object contains survey header fields (`pip_id`, `country_code`, `surveyid_year`, `welfare_type`, `poverty_line`, `analysis_var`, `measures[]`), a fixed 4-slot `layout` object (`columns`, `rows`, `superColumns`, `superRows`) with ordered registry categories, and an array of observed `cells[]` with fixed slot keys (`superRow`, `row`, `superColumn`, `column`) and a `measures` object.
- Added exported pure serializer `serialize_table_response()` and helper `build_table_layout()`.
- Added canonical `{code, label}` categories for `pov_status` (`0`: "Non-poor", `1`: "Poor") to the variable registry.
